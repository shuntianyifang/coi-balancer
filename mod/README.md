# 游戏内配平计算器（首版）

UI-only只读 Mod，目标版本0.8.7d。使用游戏原生区域选择工具；在只读同步事件读取配置快照，不注册原型、模拟服务或游戏存档数据。计算器自身方案保存在 Mod 目录的 `plans` 中。

## 使用

1. 用 `build-mod.ps1 -GameDirectory <游戏目录>` 构建，再运行 `install-mod.ps1`。
2. 在游戏中为测试存档启用“配平计算器”。按 F8 或右上角按钮打开窗口。
3. “框选追加”按实体ID去重；“框选替换”重建选择；“重新读取”更新配置并移除已拆除建筑。
4. “移除本组”“清空”仅改变计算器快照；“保存快照”写入独立JSON，不修改游戏存档。

只统计已建成建筑，一次最多1000座。每座机器的数据仍独立保存，同设置合并展示。暂停机器不产生物料流量，配置工人仍保留。基础维护按选中建筑配置估算，区分等级；不模拟实际动态维护、停机减免。显示的净耗电和物料流量来自已支持项。

目前支持普通MachineProto、恰好一个已指定配方、无额外速度/周期/虚拟产出修正；加速物料流量按游戏文档的精确x2规则计算。多配方排程、特殊建筑和未核验的修正会显示原因并标记汇总不完整，不能把它们当作零消耗或完整工厂总量。快照是配置产能，状态字段展示缺料等状态，但不据此推断实际长期产量。

首版不包含整数优化、自动建造、修改游戏运行设置或实际产量采样。特殊核电、农场、发电设备待分别接入。不将桌面版Python求解引擎载入游戏。

## 测试与存档增删

`test-mod.ps1` 运行独立C#快照测试与只读源码检查；`check.ps1` 验证现有计算器。编译与静态检查不能替代游戏内验证。

存档验证必须使用测试副本：

1. 不启用本Mod，保存测试基线。
2. 加入本Mod加载基线；确认按钮、窗口和框选正常，框选不会建造、拆除或改变配方。
3. 框选装配机I，确认建筑零件配方铁4.5、木材4.5、混凝土板6 → 建筑零件6 /60；再试重复追加、暂停后重新读取和移除。
4. 另存为测试存档，退出并禁用本Mod，加载该存档。
5. 确认建筑、库存、配方和科技完整，再另存并重新加载；重新加入Mod也能加载。

清单完成前只能声称“按可增删架构实现”，不能声称无损验证通过。游戏升级可能改变接口，按版本记录验证。不要对重要存档做首次测试。
