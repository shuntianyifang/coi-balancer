# CoI 配平工作台 v0.4

本地运行的 Captain of Industry 生产配平计算器，中文界面，Python + SciPy HiGHS 求解器，无需前端构建。项目原创代码采用 [MIT License](LICENSE)。第三方图标与资料的版权说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 新机器快速开始

需要 Python 3.10 或更高版本；运行 JavaScript 测试还需要 Node.js。Windows 在项目目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

其他系统可在项目目录运行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py
```

然后打开 http://127.0.0.1:8765/ 。核电模型入口：http://127.0.0.1:8765/?example=reactors 。服务只监听本机。

Git 仓库不包含下载的 Wiki PNG、原始页面快照及本地截图。新机器默认使用自绘图标。需要 Wiki 图片时，可主动运行 `python fetch_wiki_icons.py` 下载并保存许可说明；本地已有图标保持可用。

## 核电专用模型

加载“核电站专用模型”，或打开 http://127.0.0.1:8765/?example=reactors 。旧简化示例兼容保留。

- 三种反应堆独立建筑类型：I 型 1–3 档；II 型与 FBR 1–4 档。II 型支持铀棒/MOX，FBR 支持 0/1/3 倍增殖，增殖实际供料比例独立于核心燃烧。自动模式按输入的平均档位计算，最低第一档，不模拟自动控制。
- 27 条运行/燃料/发电配方包含制棒、浓缩、MOX、毯式与核心制造、再处理及辅助耗材。黄饼、HF、钢、酸、熔融玻璃和盐为明确外部输入边界；不声称包含它们的上游制造厂。
- 电站组隔离蒸汽和机械功。组内设备视为已连接。补齐配套会添加真实汽轮机、发电机与冷却塔卡片；重复点击只补不足容量。
- 容量报告使用线性规划，先最大化组内理想稳态电力，再回收水。无蒸汽或无机械功不会产生电力；发电机瓶颈会限制汽轮机运行。输出为供水和燃料满足时的容量结果，不能代替真实启停或轴充能模拟。
- 核算使用容量分配后的设备运行量，保留全部配置建筑与工人；列出燃料、辅助耗材缺口。电力/机械功单位为 MW，物料单位为 /60。
- 连续/整数优化固定卡片中的反应堆设置，设计辅助链；可设置电力目标和各电站外部供水上限。默认优化加权成本，并不最大化电力，因此可以选择绕过某级汽轮机直接冷凝蒸汽。需要净发电目标时在“电力 MW”行填写。
- “把优化结果转为建筑”使用求解时场景快照生成辅助建筑，保留反应堆；随后可核算验证。
- 贫铀、钚和裂变产物默认明确允许剩余，全部在结果列明。禁用后可能无解。

### 数据与边界

核电数据在 web/nuclear-catalog.json，浏览器镜像在 nuclear-catalog.js。修改项目预置数据时两者需保持一致；用户修改场景 JSON 不需要改镜像。Wiki 原始配方页面快照保存在 research/*.html.txt，结构化提取在 research/wiki-recipes.json；research_nuclear.py 仅用于研究采集。数据标为待游戏核验。

机制参考：https://coigame.com/Blog/update3-is-out ，设备参考对应 Wiki 的 Nuclear_Reactor、Nuclear_Reactor_II、Fast_Breeder_Reactor 及配方 source 字段。Update 3 的核心回收采用 16→12（75%）；不使用旧正文的 80%。乏燃料直接制毯采用 1→1、30 秒，并包含酸、玻璃与盐，纠正旧简化示例的 1→3。

汽轮机的机械功在 Wiki 中有瞬时功率与 /60 蓝字显示口径；模型使用 48 蒸汽/60 对应超高压 18、高压 II 12、低压 II 6 MW，发电机 18 MW 机械功→15 MW 电力。为了复用物料矩阵，机械功作为稳态 MW 系数存储。启动库存、热容量、应急冷却耗水、轴拓扑、启停损失、游戏难度及科技倍率没有自动模拟。维护仍采用配置配方运行量加权估算，算力记录在配方字段但尚未约束计算中心容量。

测试新增全部档位与燃料、FBR 三模式、增殖独立、发电机瓶颈、跨组隔离、回水与补水、供水约束、完整燃料链、JS/Python 结果一致性。

## 建筑卡片

每张卡片代表一座建筑，可添加、复制、移除、设置负荷和停机。选择建筑可用配方后实时计算单座输入/输出及全厂物料汇总。核算 API 以 instances 为准；优化器按配方约束设计新方案，不改变已配置建筑。

数据增加 buildings（建筑类型定义）和 instances（独立建筑实例），配方通过 buildingId 指定适用类型。多个配方设置相同 buildingId 即可在该类建筑中切换。旧方案的 count/load 首次加载自动转换成卡片；非整数数量用一座部分负荷建筑表示。示例建筑映射未核验，没有推断哪些核燃料配方共用游戏建筑。

图标优先使用本地缓存的 Captain of Industry Wiki PNG，缺失时回退自绘 SVG。建筑卡片提供来源和许可折叠项；web/icons/WIKI-LICENSES.md 保留各文件原许可文字，wiki-manifest.json 记录原图地址、来源文件页、采集时间及 SHA-256，wiki-notices 保存原文件页快照。版权与许可说明沿用来源，不视为新的开源授权。

fetch_wiki_icons.py 可联网重新采集当前八张图标。配方的 wikiIcon 字段可指定清单内文件名；建筑的 icon 可指定 /icons/ 下本地文件。旧方案使用自绘图标时自动升级为 Wiki 图标，自定义图标保持不变。示例映射仅作为视觉参考，配方所用真实建筑仍需核验。

测试：Python 单元测试以及 `node test_buildings.js`。

新增整数建筑优化：每条配方独占整数建筑，允许部分负荷；勾选强制满载时，运行量必须等于整数建筑数量。可限制总建筑数。目标为建筑数量×配方成本 + 进口数量×进口成本，另以很小的运行成本打破平局。最多求解 20 秒，未证明最优时不报告成功。

支持将成功结果加入多个方案比较，按物料比较进口流量，导出带场景快照的结果 JSON。未交叉验证或缺少来源的配方会显示数据校验提醒。工人数现按配置建筑计算，电耗与维护仍是运行量加权估算。

本地中文网页，Python + SciPy HiGHS 求解器。无需前端构建。

## 启动

在 PowerShell 中运行 `powershell -ExecutionPolicy Bypass -File D:\CoI\coi-balancer\start.ps1`，浏览器打开 http://127.0.0.1:8765 。用 Ctrl+C 停止。

当前环境依赖位于 D:\CoI\.venv。换机器时启动脚本会创建项目内虚拟环境并安装 requirements.txt。

## 使用

1. 加载示例，或导入 JSON。
2. 在 JSON 中编辑配方、周期、来源、版本与校验状态，点击应用。
3. 核算模式填写建筑数量和负荷；求解模式填写最小/最大等效运行量。
4. 设定物料目标，明确允许进口和允许剩余。
5. 计算后检查资源剩余、建筑负荷。保存方案到浏览器，或导出 JSON。

求解最小化配方运行成本和进口成本，默认严格物料平衡；没有自动免费进口或默认丢弃。所有速率按模拟秒 /60，农业完整轮作需手动转换成同一时间口径。输入输出保留单次数量和周期，避免把显示速率当单次配方。

## 数据可信度

附带配方是演示数据，不是经过核验的游戏数据库。核电示例基于历史讨论，不含完整辅助耗材、电力和启动库存。农业为合成轮作接口示例。不要直接用于建造；应替换为目标游戏版本的导出或实测值。来源和校验状态会随方案一起保存。可复制方案分别输入候选数据进行比较。

## 范围和限制

- 稳态连续线性配平；支持循环、多输入输出、进口容量、副产物积累、固定运行量。
- 连续模式建筑建议向上取整；整数模式联合优化建筑数和负荷，可对指定配方强制全满载。
- 每个配方独占建筑；不支持同机排程、科技倍率自动叠加、农业肥力动态、运输、启动与库存模拟。
- 电耗、维护按运行量线性估算；配置工人为每座建筑工人数乘以建筑数量，科技和难度修正需写入数据。
- 自动对比最近两次成功计算的剩余流量；浏览器存储仅当前浏览器可见，重要方案请导出。

## 验证

`D:\CoI\.venv\Scripts\python.exe -m unittest -v` 在项目目录运行，覆盖普通生产链、闭环回收、进口限制、副产物、时间换算和输入校验。

### 建筑显示方式

“我的建筑”支持超大、大、中、小图标、列表、详细信息、平铺和内容八种视图。详细信息展示整组输入输出、电力和工人；其他紧凑视图可展开编辑。显示方式和合并开关保存在当前浏览器。

默认按建筑类型、配方、运行开关和负荷合并显示。核电设备还比较电站组，反应堆还比较档位、调节方式、燃料及增殖设置。数据仍逐座保存，整组编辑同时应用到组内建筑；“逐座编辑”关闭合并。合并不影响配平、导出或核电容量计算。

### Windows 桌面便携版

下载或构建便携压缩包，解压后双击 `CoI-Balancer.exe`。完整保留 `_internal` 目录。无需安装 Python、手动部署站点或登录，计算离线进行。支持 Windows 10/11，需要 Microsoft Edge WebView2 Runtime；缺少时从微软官方安装 Runtime。关闭窗口会停止后台服务。内部服务只绑定回环地址，每次自动选择空闲端口。

方案通过“保存方案”写入 `%LOCALAPPDATA%\CoI Balancer\scenarios.json`；更新、移动或删除便携目录不会删除方案。该文件损坏时会明确报错，不覆盖原文件。浏览器版存储独立，可通过导出/导入 JSON 转移方案。

开发运行：`python -m pip install -r requirements-desktop.txt`，然后 `python desktop.py`。Windows 构建：`powershell -ExecutionPolicy Bypass -File .\build-desktop.ps1`；可通过 `-Python` 指定 Python 路径。输出为 `dist/CoI-Balancer-Windows.zip`。建议使用 Python 3.11–3.14，构建系统与目标系统需同为 Windows。

默认分发包使用项目 SVG 图标，并附带 MIT 与第三方说明。Wiki 游戏图标不属于 MIT，保留原文件页许可说明。本地已下载图标可使用 `-IncludeWikiIcons` 一并打包；公开分发此类包前应确认游戏素材再分发许可。程序启动不会访问 Wiki 或自动下载图标。
